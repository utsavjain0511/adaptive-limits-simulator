Both answers match my recommendation. Here's the design — four short sections, one approval at the end (push back on any part).

1. Layout

Full-viewport 3-column grid: sidebar 220px | main (fluid) | notes 320px, each column scrolling independently. - Sidebar: the four lessons as a vertical list (number + title, active one highlighted); a chevron toggle collapses it to a 56px rail showing just the numbers. Replaces the current top stepper. - Main: a slim control bar at the top (Start/Pause/Reset · speed · load · event button), then the flow animation (~220px tall), then the existing stats strip + 2×2 charts. - Notes: lesson title, intro, "What to watch" bullets, then the lesson-specific knobs (L3 slider, L4 algorithm/presets/sliders) under a "Try it" heading. - Below ~1000px it degrades to a single column: lessons as a horizontal tab row on top, notes below the charts.

2. Flow animation (FlowCanvas, canvas + requestAnimationFrame)

One Client box on the left spanning both lanes; each lane has a Shaper box (labelled with the policy and current limit) and a Backend box (fill bar = in-flight ÷ capacity, turns warning-red past 100%). Lane A is red, lane B teal. - Dots spawn at the Client per lane at offeredRps / 25 dots/sec (300 rps ≈ 12 dots/s; capped at 40/s) and travel to the Shaper in ~0.6s. - At the Shaper each dot is admitted with probability admitted ÷ offered from the latest metrics; rejected dots turn dark, drop below the box and fade — the visible cost of shedding. - Admitted dots enter the Backend and dwell for min(mean latency, 3s), jittering inside the box, so a thrashing backend visibly stuffs up with dots while a healthy one streams through. They exit right and fade: run-colored if within SLA, gray if timed out. - Dots per lane are capped (~150) so the no-shedding case stays cheap. Paused sim = frozen dots.

3. Code changes

  • App.tsx becomes the grid shell; LessonLayout renders into the main + notes areas; Sidebar.tsx replaces Stepper.tsx (deleted); new FlowCanvas.tsx; ControlBar and styles.css restyled. Dashboard and the entire sim/ layer are untouched — no test changes.
  • useLab already exposes histories; FlowCanvas reads the latest TickMetrics per run through a ref inside its rAF loop.

4. Visual direction

Minimalist/modernist: off-white ground, near-black ink, hairline borders, no shadows or gradients, small uppercase tracked section labels (SIMULATION · METRICS · LESSON), tabular numerals for stats, the two run colors as the only accents. I'll load the frontend-design skill when I start so the typography/spacing choices aren't defaults.
